# 架构

## 全景

```
┌──────────────┐   stdio(MCP)   ┌─────────────────┐
│ MCP client   │◄──────────────►│ phone-mcp       │
│ (Claude 等)  │                │ server/ (Python)│
└──────────────┘                └────────┬────────┘
                                         │ HTTPS + Bearer
                                         │ 内容已端到端加密
                                         ▼
                            ┌────────────────────────┐
                            │ 中继 relay.py           │
                            │ relay-host:8903            │
                            │ 只见密文，无 e2e 密钥    │
                            └───────────┬────────────┘
                                        │ WSS（手机主动外连）
                                        ▼
                            ┌────────────────────────┐
                            │ 手机 App                │
                            │ AccessibilityService    │
                            └───────────┬────────────┘
                                        │ 无障碍 API
                                        ▼
                                   手机屏幕
```

## 为什么让手机主动外连

手机在 NAT / 移动网络后面，电脑无法直接连它。反过来：手机启动后主动向中继建一条长连接，中继把电脑的请求塞进这条通道。

好处：
- 手机换 WiFi、切 4G 都不用改配置
- 不需要路由器端口映射
- 中继是唯一对外入口，收敛攻击面

代价：手机必须保持连接（靠前台服务防杀）。

## 三端职责

### 手机端（Kotlin）

| 模块 | 职责 |
|---|---|
| `service/PhoneMcpService` | **无障碍能力唯一持有者**。所有树读取、点击、手势、截图都从这里走 |
| `service/MoneyGuard` | **资金保护**：包名/目标链/整屏三道闸，编译期常量，无远程开关 |
| `service/KeepAliveService` | 前台服务，防 ROM 回收进程 |
| `service/StopButton` | 底部状态条：步骤进度 + 中断 + 断开提示（三模式共用一条窗口） |
| `service/HumanOverride` | 中断状态，只有 `stopped` 一个标志 + 10 秒保持期 |
| `tree/TreeSerializer` | 树 → 紧凑 JSON（短键省 token），带节点数上限 |
| `tree/SnapshotStore` | 最近 4 个快照的节点指纹，跨快照重定位 |
| `action/NodeLocator` | DFS 精确/模糊匹配 |
| `tunnel/TunnelClient` | WSS 客户端，指数退避重连 |
| `http/ControlServer` | 局域网直连（默认关闭，需手动开） |
| `util/SecretStore` | Keystore AES-GCM 加密凭据 |

### 中继（Python / aiohttp）

- `/tunnel` 收手机 WSS，`/device/<id>/<path>` 收电脑请求
- 请求/响应用 `id` 配对；手机掉线时在途请求**立即**失败，不干等超时
- 配对：`POST /pairings` 生成一次性码，`POST /pair` 兑换，`DELETE /devices/<id>` 撤销
- 注册表 `/var/lib/phonemcp-relay/registry.json`（0600），只存凭据的 SHA-256 摘要

### MCP 端（Python）

| 模块 | 职责 |
|---|---|
| `server.py` | 15 个工具 |
| `bridge.py` | 传输层，中继/直连双模式共用同一契约 |
| `render.py` | JSON 树 → 行式文本（省 3-5x token） |
| `config.py` | 环境变量解析，两种模式互斥 |
| `pairing.py` | 配对 CLI |

## 关键设计决策

### 节点 id 只在一份快照内有效，但保留 4 个版本

模型经常「dump 树 → 点 n12 → 点 n15」，中间任何一次 UI 刷新不该让 id 全失效。所以保留最近 4 个快照的指纹（viewId + 文本 + 坐标），失效时明确报错而不是静默点错。

### 动作拆两阶段

NodeInfo 有线程亲和性，只能在主线程操作；手势回调又必须主线程等。所以：

```
阶段 1（主线程）：定位节点 + performAction
阶段 2（后台线程）：不可点时用手势兜底
```

### 内容端到端加密，中继不可信

中继是唯一能看到全部流量的节点，所以**不把它当作可信方**：指令与截图用
AES-256-GCM 加密后再经它转发。密钥随配对二维码在电脑与手机间直接分发，
中继没有任何获取途径。

这样即使中继主机被攻破，攻击者也只能拿到密文和元数据（谁、何时、多大）。

### 中断靠用户主动点

Android 无法区分 `dispatchGesture` 注入的手势和真人触摸（系统层面完全一致，无任何标记）。任何自动判定都会在「误判自己」和「漏掉用户」之间摇摆。

所以：**底部悬浮条，用户点一下才中断**。语义明确、零误判。

中断信号必须抛 `ToolError`——返回值会被模型当成"工具成功"而继续执行。

### 底部条同时承担进度显示

用户需要知道 AI 现在在干什么，否则只能看到一个自动滚动的屏幕。所以每个工具都接受
`step` 参数（一句中文短语），随请求体下发到手机端，显示在底部条的胶囊上；
展开面板还能看到最近 5 步、累计步数和耗时。

`step` **只作展示，不作安全判据**——模型完全可以写「查看设置」然后去点别的地方。
硬约束只有 `MoneyGuard`。

同一条窗口还承担第三种用途：中继断开时变橙色显示原因，并提供「立即重连」。
三种模式（动作 / 连接 / 隐藏）共用一条悬浮窗，避免屏幕上同时挂两条。

### 资金保护在手机端，不在提示词里

模型是不可信输入源（页面里藏一句提示注入就能让它「帮我付一下」），所以资金保护
不能靠系统提示，也不能靠电脑端参数检查——APK 版本旧了就绕过。

拦截放在手机端 `MoneyGuard`：包名、目标节点及其父链、整屏文字，三道闸全部在
`AccessibilityService` 里判定。策略是**编译期常量**，MCP 的 15 个工具里没有一个
能读写它，也没有环境变量能关掉。服务端的 `moneyguard.py` 只是参数级兜底。

读取同样受保护：资金类 App 的截图和界面树直接拒绝——付款码是不记名凭证，
余额和卡号本身就是敏感数据。

## 数据流：一次 `phone_observe`

```
1. MCP client 调 phone_observe
2. server.py → bridge.post("/screenshot") + bridge.post("/tree")
3. bridge → HTTPS → 中继 → WSS → 手机
4. 手机：takeScreenshot() 拿图，dumpTree() 序列化
5. 反向返回；server.py 拼成 [Image, text] 两个内容块
6. 模型同时看到图和树
```
