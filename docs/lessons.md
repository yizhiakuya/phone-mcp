# phone-mcp 踩坑记录

真实设备上踩出来的经验。每条都标注了**版本**和**现象**，方便判断自己遇到的是不是同一个问题。

格式：`现象 → 根因 → 处理`。只收录**会重复遇到**的，一次性的调试细节不放。

---

## 定位与点击

### 图标类控件只有 contentDescription，没有 text

**现象**（≤1.1.15）：`phone_click(text="哔哩哔哩")` 返回 404「没找到匹配的节点」，
但 `phone_ui` 里明明看得到这个节点。

**根因**：`NodeLocator.matches()` 里，只要传了 `text` 就要求 `node.text` 必须存在。
但桌面图标、工具栏按钮这类控件只有 `contentDescription`，`text` 是 null。

**处理**：1.1.16 起 text 与 desc 互相兜底——只给其中一个时，另一个字段也参与匹配。

**教训**：看到「树里有但点不到」，先确认该节点的文本到底在 `t` 还是 `d` 字段。

### 节点 id 跨快照错位

**现象**（≤1.1.15）：`phone_ui` 拿到 n37 是「哔哩哔哩」，下一次 `phone_ui` 后
用 n37 点击，打开的是「高德地图」。

**根因**：`TreeSerializer` 用 `"n${refs.size}"` 编号，每次 dump 都从 n0 重新开始。
`SnapshotStore` 保留 4 个版本，但 id 字符串重复，查询时只能命中最新版本——
旧 id 静默解析成另一个控件。

**处理**：1.1.16 起改为全局单调递增计数，id 跨快照唯一。

**教训**：这是**静默错误**，比报错危险得多。凡是要用旧 id 的地方，
都该假设它可能指向别的节点。

### 坐标点在两列图标之间

**现象**：`phone_tap(640, 1400)` 返回「成功」，但什么都没打开。

**根因**：抽屉是 4 列布局，x=640 正好落在第 2 列（345–634）和第 3 列（690–891）
中间的空隙里。手势确实执行了（手指碰了屏幕），但没碰到任何控件。

**处理**：1.1.12 起加了落点体检——坐标下没有可点控件时返回
`warning: 该坐标下没有可点击的控件`；手势成功但界面无变化时返回 `no_effect`。

**教训**：`dispatchGesture` 返回成功**只代表手指动了**，不代表界面响应了。
能用文本定位就别用坐标。

### 慢速上滑打不开应用抽屉

**现象**：`phone_swipe(640, 2000, 640, 700, 600)` 打不开 MIUI 抽屉，
但 400ms 可以。

**根因**：手势时长过长，系统判定为拖拽而非快速上滑。

**处理**：MIUI 抽屉用 400ms。不同 ROM / 不同手势的合适时长不一样，
遇到「滑了没反应」先换时长试。

## 线程与死锁

### 截图超时（5s / 8s）

**根因**：`callOnMain { takeScreenshotBlocking() }`。截图回调投递到主线程，
而主线程正被 `latch.await()` 阻塞 → 死锁。

**处理**：截图必须在后台线程直接调，不能包 `callOnMain`。

**同类**：`dispatchGesture` 的回调也在主线程，手势等待同样不能在主线程做。

### 无障碍服务被系统自动关闭

**现象**：操作一阵后无障碍失效，`/health` 里 `root_available: false`。

**根因**：主线程阻塞导致 ANR，系统判定无障碍服务异常并禁用。
曾经的元凶是 `waitForIdle` 在主线程 `Thread.sleep` 轮询。

**处理**：轮询类逻辑一律放调用线程，每次取指纹单独切主线程。

### `inflight` 不归零

**根因**：动作直接在 OkHttp 的 WebSocket 读线程上同步执行，一个卡住就堵死整条连接。

**处理**：单线程 `worker` 执行器串行执行动作，读线程立刻返回。

## 交互与文案

### 中断信号返回字符串，模型不停手

**现象**：用户点了中断，工具返回「用户已中断」，但模型继续调下一个工具。

**根因**：返回值会被模型当成「工具正常执行完了」。

**处理**：必须 `raise ToolError(...)`。只有工具调用失败，模型才会停下来重新规划。

**同理**：资金保护拦截也必须抛 `ToolError`。

### 点歪了但界面没变化，模型以为成功了

见上文「坐标点在两列图标之间」。`no_effect` 信号就是为这个加的。

## 资金保护

### 微信首页被锁死

**现象**（1.1.12）：打开微信，连滚动都被拒，提示「命中『提现』」。

**根因**：两个问题叠加——
1. 整屏扫描**包含不可见节点**。微信首页挂着一条不可见的广告横幅
   「微信支付提现笔笔省」，`bounds=None`。
2. 「提现」这种泛词太宽，广告语、聊天消息里到处都有。

**处理**：1.1.13 起整屏扫描跳过 `!isVisibleToUser`；整屏词表移除
`提现 / 充值中心 / 花呗 / 借呗 / 余额宝 / 零钱通` 等泛词，只保留支付页独有的字段名
（`确认支付` `付款码` `转账金额` `收款方` `实付款`）。

**教训**：**误伤比漏拦更危险**。App 被锁死用户会直接卸载，反而失去保护。
判断标准：看到这个词，能不能确定"用户此刻真的在支付页上"。

### 支付页连滚动都被拦

**现象**：微信「服务」页上 `phone_scroll` 被拒，用户没法往下翻找功能。

**根因**：整屏判定把滚动也算成「改动操作」。

**处理**：1.1.14 起 `scroll` 走只读通道，跳过整屏判定（仍查包名）。
**刻意没放行裸 `swipe`**——滑动能用来画支付密码九宫格，语义不明确。

## 加密与传输

### 响应是空 `{}`

**根因**：中继旧实现只透传 `reply["body"]`，而加密响应用的字段是 `e2ee`。

**处理**：中继遇到 `e2ee` / `plain_error` 原样透传。

### `e2ee_fail|key=len43 ... AEADBadTagException`

**根因**：两端参数不一致（nonce 位置、AAD 格式、base64 变体）。

**处理**：重新配对通常能解决。调试时让手机端回**明文诊断**（`replyPlain`）——
用错误的密钥加密错误消息会形成死锁，什么都查不到。

### 中继把长等待掐断

**现象**：`phone_watch(timeout_ms=120000)` 在 60 秒处返回 504。

**根因**：中继默认 `REQUEST_TIMEOUT=60`。

**处理**：1.1.15 起 `/watch`、`/wait_until` 用 `LONG_POLL_TIMEOUT=150`。

## 构建与发布

### 无障碍服务每次更新 APK 后失效

**现象**：装完新版，无障碍显示已连接但读不到窗口。

**处理**：到系统设置里关掉再打开一次无障碍服务。这是 Android 的限制，无法绕过。

### MIUI 无法启动其他 App

**现象**：`phone_launch` 报「启动被系统拒绝」。

**处理**：授予「后台弹出界面」权限。

### release 签名回落到 debug

**现象**：新 APK 装不上，提示签名冲突。

**根因**：`keystore/keystore.properties` 不存在时，`build.gradle.kts` 不会配
signingConfig，回落到 debug 签名。

**处理**：`build_apk.sh` 会校验签名 DN 必须是 `CN=Phone MCP`，不匹配直接中止。
keystore 在 `android/keystore/`（已 gitignore），**丢了就无法覆盖升级**。

### `relay.py` 与 `server/relay_pkg/relay.py` 不一致

**现象**：`test_deployed_relay_matches_tested_copy` 失败，报字节不同。

**根因**：两个文件本来是硬链接，Windows 的 CRLF 转换把它们拆成了独立文件。

**处理**：`cp relay/relay.py server/relay_pkg/relay.py` 重新同步。

## 录制回放

### 回放时 `node_id` 必然失效

**根因**：node id 是单次快照内的编号，换一次界面就没了。

**处理**：录制时从返回的 `target` 里解析出 `text` / `desc` / `view_id` 存进
`fallback`，回放时用它们重新定位。解析不出来就只能依赖原参数，通常会在该步失败。

### 录制没录到某一步

**检查顺序**：
1. 那一步是不是失败了（失败不录）
2. 那一步是不是 `no_effect`（手势成功但界面没变化，也不录）
3. 那一步是不是读取类工具（`observe` / `ui` / `find` 不录）

## 通用方法论

1. **静默错误比报错危险**。点歪了返回「成功」、旧 id 指向新节点，这类问题
   不会让你立刻发现，但会让整条链路歪掉。宁可多返回一个 warning。
2. **误伤比漏拦危险**。尤其是安全策略——把正常功能锁死，用户会直接弃用。
3. **能用语义定位就别用坐标**。文本/描述/id 会随界面更新而失效并报错，
   坐标不会报错，只会点错。
4. **改 Android 端前先读 `docs/threading.md`**。四个死锁/ANR bug 都是同一类错误。
5. **验证要上真机**。假服务测不出 ROM 差异、无障碍事件时序、坐标布局。
